# Topo AI — веб-анализатор топографических карт

Веб-приложение на Python (Streamlit), которое распознаёт высоты на топографических картах через OCR, позволяет редактировать найденные точки, привязывает их к известному геодезическому пункту и строит тепловую карту рельефа в реальных метрах.

Проект создан в рамках учебной практики по направлению **21.03.02 «Землеустройство и кадастры»**. Он демонстрирует полный цикл обработки топографической карты: от загрузки исходного материала до получения интерактивной модели рельефа.

## 📌 Что умеет приложение

| Возможность | Описание |
|---|---|
| **Загрузка карт** | PNG, JPG, JPEG, PDF (PDF автоматически рендерится через PyMuPDF в 300 DPI) |
| **Автоопределение DPI** | Из метаданных JPG/PNG или по размеру страницы и встроенной картинки PDF. Если не удалось — 300 DPI |
| **Выделение горизонталей** | OpenCV + фильтрация контуров по форме: отсекаются текст, здания, дороги и рамки |
| **Распознавание высот** | EasyOCR находит числовые подписи (например, «285,19») и их координаты |
| **Редактор точек** | Таблица с возможностью исправить высоту, координаты, удалить строку или добавить новую |
| **Привязка к кресту** | Если известны пиксельные координаты одного геодезического пункта и его реальные координаты — все точки пересчитываются в реальную систему |
| **Тепловая карта** | Интерполяция высот (SciPy griddata: cubic → linear → nearest) и интерактивный график Plotly |
| **Масштаб** | Задаётся в боковой панели (только 1:N — DPI определяется автоматически) |
| **Экспорт координат** | Таблица реальных координат всех точек в метрах отображается на экране |

## 🗂️ Архитектура проекта

```
topo/
├── app.py                  ← веб-интерфейс (Streamlit)
├── topo_ai.py              ← загрузка карт + OCR высот
├── heatmap_generator.py    ← построение тепловой карты
├── requirements.txt        ← зависимости
├── .streamlit/
│   └── config.toml         ← настройки Streamlit (порт, CORS)
└── README.md
```

### `app.py` — веб-интерфейс

Главный файл. Содержит:

- **`auto_detect_dpi(image_path)`** — определяет DPI из метаданных изображения или из структуры PDF. Если не удалось — возвращает 300.
- **`filter_contours_by_shape(binary_mask, min_area, max_area, max_rectangularity, min_vertices)`** — фильтрует контуры OpenCV, оставляя только те, что похожи на горизонтали (тонкие, извилистые, с большим числом вершин).
- **`resize_for_ocr(image, max_side=1500)`** — уменьшает изображение перед OCR, чтобы не выедать память Codespaces.
- **`to_real_coords(heights, mpp, anchor)`** — пересчитывает пиксельные координаты в метры с учётом масштаба и привязки к кресту.
- Боковая панель: масштаб 1:N, опциональная привязка к кресту.
- Основной блок: загрузка, отображение карты, маска горизонталей, OCR с прогресс-баром, редактор таблицы, построение карты.

### `topo_ai.py` — загрузка карт и OCR

- **`load_image(path, dpi=300)`** — открывает PDF (первая страница, рендер через PyMuPDF) или изображение (OpenCV). Возвращает BGR-массив.
- **`extract_heights(image)`** — запускает EasyOCR на изображении, фильтрует результаты по формату числа и диапазону высот (0–9000 м). Возвращает список словарей `{value, x_px, y_px, confidence}`.

### `heatmap_generator.py` — тепловая карта

- **`create_heatmap(points, output_html, grid_size=100)`** — строит интерактивный Plotly-график. Точки уже в реальных метрах. Пробует методы интерполяции по очереди: `cubic` → `linear` → `nearest`. Заполняет NaN на краях методом `nearest`.

## 🧭 Как пользоваться

### Шаг 1. Задать масштаб

В **боковой панели** введите масштаб карты, например `2000` для 1:2000. DPI программа определит сама.

**Формула пересчёта масштаба в м/пиксель:**

```
м/px = (N / 100) × 2,54 / DPI
```

Пример: масштаб 1:2000, DPI 300:
```
м/px = (2000 / 100) × 2,54 / 300 = 20 × 2,54 / 300 = 0,169333 м/px
```

### Шаг 2. Загрузить карту

Перетащите файл в поле загрузки. Приложение:

- определит DPI;
- покажет исходную карту;
- выделит горизонтали (если они есть);
- запустит OCR (прогресс-бар покажет статус).

### Шаг 3. Отредактировать точки

После OCR появится **редактируемая таблица**:

- исправить значение высоты;
- исправить координаты `x_px`, `y_px`;
- удалить ошибочную строку (выделить и нажать `Delete`);
- добавить новую точку (кнопка `+` внизу таблицы).

Если что-то сломалось, нажмите **«Сбросить (вернуть OCR)»**.

### Шаг 4. Привязать к кресту (опционально)

Если на карте есть геодезический пункт с известными координатами:

1. Включите чекбокс **«Привязать к известному кресту»**.
2. Найдите пиксельные координаты креста (откройте картинку в Paint и наведите курсор — позиция показывается внизу окна).
3. Введите реальные X и Y этого пункта в метрах.
4. Красный крест появится на исходной карте для проверки.

Без привязки координаты отсчитываются от левого нижнего угла изображения (X — вправо, Y — вверх).

### Шаг 5. Построить тепловую карту

Нажмите **«Построить тепловую карту»**. Приложение:

- пересчитает координаты в реальные метры;
- покажет таблицу координат;
- построит интерактивную тепловую карту (Plotly), где цвет = высота, а точки подписаны значениями.

Тепловая карта строится **даже если горизонталей на карте нет** — только по отметкам высот из OCR.

## 🧠 Как работает распознавание высот

1. **Подготовка изображения.** Карта уменьшается до 1500 px по длинной стороне (`resize_for_ocr`). Это в 3–5 раз ускоряет OCR и экономит память.

2. **Запуск EasyOCR.** Библиотека использует две нейросети:
   - **Detector** — находит области, где есть текст;
   - **Recognizer** — распознаёт символы в каждой области.
   
   Модели обучены на русском и английском языках (`reader = easyocr.Reader(["ru", "en"], gpu=False)`).

3. **Фильтрация результатов.** Для каждой найденной текстовой области:
   - текст очищается от пробелов и заменяет запятую на точку (`text.replace(",", ".").replace(" ", "")`);
   - проверяется, является ли результат числом (`float(cleaned)`);
   - проверяется диапазон (`0 < value < 9000`) — высоты на топокартах обычно в этом диапазоне;
   - проверяется минимальная длина (`len(cleaned) >= 2`) — одиночные цифры отсекаются, так как это чаще всего шум.

4. **Координаты.** Для каждой области берётся центр ограничивающего прямоугольника `(cx, cy)`.

5. **Возврат результата.** Список словарей `{value, x_px, y_px, confidence}`, где `confidence` — уверенность OCR (0..1).

**Почему не все высоты находятся:**

- Мелкий шрифт (< 8 px) — EasyOCR может не распознать;
- Плохое качество скана (шум, артефакты) — падает точность;
- Кириллица + цифры в одном слове (например, «г. 285,3») — фильтр по `float` отбросит;
- Высота написана с индексом или другим разделителем (например, «285³») — не распознается как число.

В таких случаях точки можно **добавить вручную** в редакторе.

## 📐 Как работает привязка к кресту

### Без привязки

Координаты отсчитываются от **левого нижнего угла изображения**. Ось X — вправо, ось Y — вверх.

```
X = x_px × mpp
Y = −y_px × mpp
```

Знак минус перед Y нужен потому, что на изображениях ось Y направлена **вниз**, а на картах — **вверх** (север сверху).

### С привязкой

Если известны реальные координаты одного пункта (креста) на карте, все точки пересчитываются относительно него:

```
X = X_anchor + (x_px − x_anchor_px) × mpp
Y = Y_anchor − (y_px − y_anchor_px) × mpp
```

Где:

- `X_anchor`, `Y_anchor` — реальные координаты креста (в метрах);
- `x_anchor_px`, `y_anchor_px` — пиксельные координаты креста на изображении;
- `mpp` — метров на пиксель;
- `x_px`, `y_px` — пиксельные координаты точки.

**Пример:**

Крест на карте имеет пиксельные координаты `(1500, 800)` и реальные `(7435621.5, 4310288.3)` м. Точка высоты находится в `(1600, 900)` пикселях. Масштаб 1:2000, DPI 300 → `mpp = 0.169333`.

```
X = 7435621.5 + (1600 − 1500) × 0.169333 = 7435638.43 м
Y = 4310288.3 − (900 − 800) × 0.169333  = 4310271.37 м
```

### Ограничение

Если карта **повёрнута относительно севера**, привязка по одной точке даст правильные смещения, но не поворот. В этом случае нужны две точки, чтобы вычислить угол. Функция привязки по двум точкам — в планах развития (см. Roadmap).

## 🗺️ Как строится тепловая карта

1. **Подготовка данных.** Из редактора берутся точки с непустыми `value`, `x_px`, `y_px`. Они пересчитываются в реальные метры через `to_real_coords`.

2. **Проверка минимума.** Для интерполяции нужно **минимум 3 точки**. При меньшем числе выводится предупреждение и наносится исходное изображение с точками.

3. **Построение сетки.** Создаётся сетка 100×100 в прямоугольнике `[min(x), max(x)] × [min(y), max(y)]`. Параметр `grid_size` можно менять.

4. **Интерполяция (`scipy.interpolate.griddata`).** Методы пробуются по очереди:
   - **`cubic`** — кубическая интерполяция, гладкая, но требует ≥ 4 точек, не всегда сходится;
   - **`linear`** — линейная, работает при ≥ 3 точках, но оставляет NaN за пределами выпуклой оболочки;
   - **`nearest`** — ближайший сосед, заполняет всё, но грубый.
   
   Первый удачный метод используется как основной.

5. **Заполнение NaN.** Если выбранный метод оставил дырки (чаще всего по краям), они заменяются значениями из `nearest`. Итоговая поверхность не имеет пропусков.

6. **Визуализация.** Строится **два слоя Plotly**:
   - **`Contour`** — контурный график с цветовой шкалой `Jet` (синий — минимум, красный — максимум);
   - **`Scatter`** — точки с подписями значений.
   
   Оси: X (м), Y (м). В заголовке — «Тепловая карта высот (оси в метрах)».

7. **Экспорт.** Результат сохраняется в `temp_heatmap.html` и показывается в Streamlit через `st.iframe`. Файл можно открыть в браузере отдельно, отправить заказчику или вставить в отчёт.

**Ограничения:**

- Тепловая карта — это **модель**, а не точный рельеф. Погрешность зависит от плотности и качества точек.
- При малом числе точек (3–5) поверхность будет грубой.
- За пределами выпуклой оболочки точек значение экстраполируется методом `nearest` — это условно.

## 🔍 Как найти пиксельные координаты креста

1. Откройте карту в любом просмотрщике с отображением курсора:
   - **Paint** — позиция внизу окна;
   - **IrfanView** — в строке статуса;
   - **Photoshop** — в панели «Инфо»;
   - **GIMP** — в строке статуса.
2. Наведите курсор на центр креста. Внизу окна будет показана позиция в пикселях — это `x_px`, `y_px`.
3. Реальные координаты `X_real`, `Y_real` указаны рядом с крестом на самой карте (например, «X = 7435621,5; Y = 4310288,3»).

**Важно:** пиксельные координаты считаются от **левого верхнего** угла изображения (0,0). Если программа показывает позицию от левого нижнего — пересчитайте: `y_px = height − y_снизу`.

## 🛠 Возможные проблемы и их решение

| Проблема | Причина | Решение |
|---|---|---|
| `ModuleNotFoundError` | Не установлены зависимости | `pip install -r requirements.txt` |
| `PDFInfoNotInstalledError` | В коде остался `pdf2image` | Удалите `pdf2image` из `requirements.txt` и проверьте, что `topo_ai.py` использует PyMuPDF |
| `Connection failed with status 404` | Streamlit упал или отвалился WebSocket | Проверьте `.streamlit/config.toml`, перезапустите `streamlit run app.py` |
| `MemoryError` или `Killed` | EasyOCR выедает память | Уменьшите `max_side` в `resize_for_ocr` до 1000 |
| OCR долго работает | Первый запуск скачивает модель (~100 МБ) | Подождите 2–3 минуты при первом запуске |
| Тепловая карта не строится | Меньше 3 точек | Добавьте точки в редакторе |
| Координаты «съезжают» | Карта повёрнута относительно севера | Нужна привязка по двум точкам (функция в разработке) |
| Тепловая карта в пикселях вместо метров | Не задан масштаб | Введите масштаб в боковой панели |
| `use_column_width` предупреждение | Устаревший параметр | Замените на `width='stretch'` |
| `st.iframe` предупреждение | Передаётся строка вместо `Path` | Используйте `st.iframe(Path(html_path), height=600)` |

## ❓ FAQ — частые вопросы

**Q: Почему тепловая карта в пикселях, а не в метрах?**

A: Проверьте, что в боковой панели задан масштаб 1:N (не «не использовать»). По умолчанию масштаб 2000.

---

**Q: OCR не нашёл ни одной высоты. Что делать?**

A: Возможные причины:
1. Карта низкого качества или мелкий шрифт — попробуйте увеличить исходное изображение перед загрузкой.
2. Числа написаны слитно с буквами (например, «г.285») — фильтр по `float` отбросит. Добавьте точку вручную.
3. EasyOCR не загрузил модель — проверьте интернет и терминал на наличие ошибок.

---

**Q: Масштаб задан, но координаты всё равно неправильные.**

A: Проверьте:
1. **DPI определён верно?** Программа пишет его под изображением. Если исходный скан был 200 или 600 DPI, а программа подставила 300 — масштаб ошибётся в 1,5 или 2 раза.
2. **Привязка к кресту указана?** Без неё координаты считаются от левого нижнего угла изображения, что редко совпадает с реальной системой координат.
3. **Карта ориентирована по северу?** Если нет, привязка по одной точке не решит проблему.

---

**Q: Почему тепловая карта получилась «пятнами», а не плавная?**

A: Мало точек или они распределены неравномерно. Способы улучшить:
- добавить точки в редакторе вручную в «пустых» зонах;
- использовать метод `linear` вместо `cubic` (программа выбирает автоматически, но при малом числе точек `cubic` может не сойтись);
- уменьшить `grid_size` в `heatmap_generator.create_heatmap` (например, до 50).

---

**Q: Что делать, если карта повёрнута относительно севера?**

A: Сейчас привязка работает только по одной точке (смещение без поворота). Для корректной работы с повёрнутой картой нужна привязка по двум точкам — это в Roadmap.

---

**Q: Можно ли использовать приложение для карт других масштабов (1:500, 1:10000)?**

A: Да. Введите соответствующий масштаб в боковой панели. Если DPI скана неизвестен — программа подставит 300, что верно для большинства случаев. При сомнении откалибруйтесь по километровой сетке: расстояние между двумя её линиями равно 1 км, по нему можно вычислить фактический м/пиксель.

---

**Q: Как экспортировать результат в CSV или Excel?**

A: Пока таблица координат отображается на экране. Скачать её можно через контекстное меню таблицы Streamlit (три точки справа) → «Download as CSV». Полноценный экспорт с сохранением привязки и метаданных — в Roadmap.

## 🚧 Roadmap — что можно добавить

### Ближайшие улучшения

1. **Привязка по двум точкам.** Позволит корректно работать с картами, повёрнутыми относительно севера. Формула: вычисление угла `θ = arctan2(ΔY, ΔX)` и поворот всех точек вокруг первой опорной.
2. **Экспорт координат в CSV.** Кнопка «Скачать CSV» с колонками `ID, X, Y, Z, confidence`.
3. **Работа со всеми страницами PDF.** Сейчас берётся только первая страница; можно добавить выбор страницы.
4. **Ручное добавление крестов.** Возможность задать несколько опорных точек на карте и переключаться между ними.
5. **Калибровка по километровой сетке.** Пользователь указывает две точки сетки, зная, что между ними 1 км, — программа пересчитывает м/пиксель без DPI.

### Долгосрочные

6. **Нейросеть для горизонталей (U-Net).** Обучение на размеченных данных для точного выделения горизонталей вместо эвристик OpenCV.
7. **Автоматическое определение масштаба.** Если на карте есть штамп «1:2000», распознать его через OCR и подставить масштаб автоматически.
8. **Интеграция с QGIS.** Экспорт в GeoJSON или Shapefile для загрузки в ГИС.
9. **Мобильная версия.** Адаптация интерфейса под планшеты и смартфоны.
10. **3D-визуализация рельефа.** Построение трёхмерной поверхности по тем же точкам через Plotly `Surface`.

## 📋 Технические детали

- **Формат карт:** PNG, JPG, JPEG, PDF (первая страница).
- **DPI PDF:** 300 по умолчанию, определяется автоматически по размеру страницы.
- **Формат координат:** метры от левого нижнего угла (без привязки) или от указанного креста (с привязкой).
- **Формат тепловой карты:** интерактивный HTML (Plotly), открывается прямо в Streamlit.
- **Минимум точек для карты:** 3 (метод `nearest` — при меньшем числе выводится предупреждение).
- **Используемые методы интерполяции:** `cubic` → `linear` → `nearest` (по убыванию сложности).
- **Порог фильтрации высот:** 0 < value < 9000 м.
- **Размер изображения для OCR:** до 1500 px по длинной стороне.
